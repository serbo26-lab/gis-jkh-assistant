# Карта рабочих процессов «ГИС ЖКХ Ассистент»

> Исследовательский снимок по `main` / `0.1.0.dev56`, commit `17834a5a569cc24e670005f724aad3fd5b13ce0a` (08.10.2026).
> Это **описание реализованных путей и инвариантов**, а не требование навечно оставить текущий UI. Перед любым аудитом проверять свежий main.
> Варианты улучшения UX должны быть отдельно помечены как **ПРЕДЛОЖЕНИЕ**, не подменяя текущее поведение.

## Источники

- `src/gis_jkh_assistant/app/page_layouts.py`, `workflow_widgets.py` — видимые действия, контекст и stepper.
- `docs/ux-dev54.md`, `docs/ux-dev56.md` — прежние решения и обнаруженные проблемы.
- `tests/test_ui_workflow.py`, `tests/test_registry_ui.py`, `tests/test_ui_clarity.py` — ожидаемые сценарии.

## Сквозной путь
**УО → Дома → Перечень работ → Планирование → Фиксация → Оценка качества.**
Есть обратная загрузка уже размещённых сведений из ГИС для отдельных домов и периодов; XLSX остаётся резервным способом на поддерживаемых участках. На каждом шаге текущая выбранная сущность, её жизненный цикл и ограничения должны быть видимы пользователю.

### 1. «Дома»
**Начало:** нет УО / УО есть, дома не загружены / поиском ничего не найдено / дом не выбран / дом без GIS identity / дом выбран.
**Основной путь:** добавить УО (в том числе из авторизованного кабинета при доступности helper) → загрузить реестр домов выбранной УО → выбрать дом → проверить адрес, GUID, период управления, площадь и историю тарифов → перейти к перечням.
**Вторичные действия:** ручные УО и дом; Excel-площадь/тариф; массовая загрузка управления и перечней; точечная загрузка управления.
**Ограничения:** найденные поиском 0 строк ≠ пустой реестр; загрузка из ГИС не должна уничтожать локальные тарифы, периоды и созданные пользователем сведения; ручные сведения об управлении требуют проверки перед заменой. Фоновая загрузка не должна подменять контекст работающего оператора.
**Код:** `houses_page.py` (методы `_sync_houses_from_gis`, `_sync_all_management_from_gis`, `_sync_all_work_lists_from_gis`, `_flush_autosave`), `registry_workflow.refresh_houses`.

### 2. «Перечни работ и услуг»
**Начало:** нет дома/перечня; локальный перечень пуст/заполнен; локальная проверка отсутствует; отправлен XLSX; GIS-проект; размещён; отменён; исторический; неясный статус/ошибка.
**Путь:** выбрать/создать перечень → добавить работы из справочника текущей УО (либо восстановить допустимый состав) → заполнить и проверить значения → создать/сохранить GIS-проект → дождаться обработки при необходимости → разместить → перейти к планированию.
**Функции:** импорт/экспорт XLSX как fallback; собственные шаблоны состава; создание на основе существующего; распределение суммы; загрузка перечней дома; синхронизация; отмена размещённого перечня при осознанном выборе.
**Ограничения:** не выдавать подмену перечня/периода за пользовательский выбор. Исторические строки не подменять похожими позициями нового справочника. Отмена размещённого перечня может привести к исчезновению зависимых планов/фиксаций/оценок в ГИС — перед действием раскрывать последствия. При status APPROVED состав доступен для просмотра и следующий шаг — план.
**Код:** `work_lists_page.py` (`_create_work_list`, `_load_house_work_lists_from_gis`, `_sync_current_work_list_from_gis`, `_approve_current_work_list_in_gis`, `_cancel_current_work_list_in_gis`), `registry_workflow.refresh_work_lists`.

### 3. «Планирование»
**Предпосылка:** подходящий размещённый перечень и выбранный год.
**Путь:** выбрать год → загрузить существующий план при необходимости → распределить работу по месяцам / задать даты → проверить → разместить/обновить план → перейти к фиксации.
**Вторичные:** очистить выделенные ячейки, очистить год, загрузить из ГИС.
**Ограничения:** исторический план со строками, отсутствующими в современном составе перечня, допустим для просмотра, но опасная обратная запись блокируется/объясняется. Не терять точные даты, не заменять весь год одной выбранной ячейкой. Не размещать без проверенного контекста.
**Код:** `planning_page.py` (`_distribute`, `_load_from_gis`, `_publish_to_gis`), `workflow_presenter.refresh_planning`.

### 4. «Фиксация работ и услуг»
**Предпосылка:** размещённый перечень и его доступные месяцы в году.
**Путь:** выбрать месяц для просмотра → выбрать область действий «выбранный месяц» / «доступный период» → заполнить по плану либо ввести факт вручную → проверить фактические цену/объём/количество/стоимость и при необходимости фото, внеплановые работы → разместить выбранную область → перейти к оценке качества.
**Вторичные:** загрузка текущей области из ГИС, очистка факта; работа с внеплановыми строками и фото.
**Особенность:** при области «доступный период» таблица показывает один месяц, но команда действует на все соответствующие месяцы; формирование периода может затронуть уже заполненные/размещённые месяцы и должно быть объяснено. Если очередь прервалась, можно продолжить с проблемного месяца без повторения успешных.
**Код:** `fixation_page.py` (`_scope_is_period`, `_fill_scope_from_plan`, `_publish_scope`, `_continue_queue`); `workflow_state.fixation_step`; `workflow_presenter.refresh_monthly`.

### 5. «Оценка качества»
**Предпосылка:** подходящий перечень, год/месяц и при автоматическом формировании фактические показатели; включение работ возможно и вручную.
**Путь:** сформировать оценку из факта (либо задать вручную) → проверить включённые работы → подготовить акты для размещения → **сохранить GIS-проект можно и без актов** → разместить только после соответствующей валидации → перейти к следующему невыполненному месяцу.
**Вторичные:** формирование автоматических актов для месяца/периода, ручные/импортированные акты, очистка полей перерасчёта без удаления актов и включённых работ, загрузка из ГИС, аннулирование в применимом состоянии.
**Ограничения:** обычный акт выполненных работ не требует заполнения полей ненадлежащего качества/перерасчёта; пользовательские и импортированные акты нельзя заменять автогенерацией. Проект без актов — нормальное состояние, а не ошибка сохранения.
**Область периода:** включать в отправку допустимые месяцы, сообщать об исключённых; уже размещённые месяцы не должны мешать отправке других. Сбой очереди на месяце → понятная причина и возобновление.
**Код:** `quality_page.py` (`_form_scope_from_fixation`, `_auto_generate_scope_act`, `_save_scope`, `_publish_scope`, `_validation_error`, `_continue_queue`); `workflow_state.quality_step`; `workflow_presenter.refresh_monthly`.

### 6. «Настройки» и общий контекст
**Режимы:** общий/независимый выбор; light/dark; масштаб 100/125/150; статус подключения browser helper.
**Инвариант:** при общем выборе сохранять УО, дом, перечень и год между разделами, где они применимы; отсутствующий/неразмещённый перечень не подменять случайным. Долгая операция удерживает собственный контекст до завершения. Навигация между фиксацией и оценкой переносит месяц и scope при совпадающей сущности и годе. При независимом режиме не навязывать общий контекст.
**Код:** `main_window.py` (`_capture_shared_context`, `_apply_shared_context_to_page`, `_workflow_navigation_requested`), `settings_page.py` и `ui_scale.py`.

## Правило для улучшений
Прежде чем переставлять элементы, ответь по каждому экрану: «Какое действие человек должен сделать сейчас?», «Что блокирует его и почему?», «Какие данные будут изменены и в какой области?», «Что станет следующим шагом?». Разделяй зафиксированный жизненный цикл и целевой UX.
