# Состояния, область действий и переходы UI

> Рабочая карта для GIS Workflow Architect. Снимок dev56; перед использованием сверять текущий код. Названия статусов разных сущностей **не являются единой универсальной enum**.

## Полный контекст экрана
`(organization_id, house_id, work_list_id, year, view_month, action_scope, connection_state, busy_state, remote_status, local_dirty, last_error)`.
Не все поля применимы к каждой вкладке. Отдельно фиксируй: контекст, реальную доступность команды и видимый пользователю статус. Не выводи «размещено» только по тому, что когда-то существовал remote GUID.

## Обязательные ветви состояния
| Ситуация | Основное действие/объяснение | Проверка |
| --- | --- | --- |
| Нет УО | Добавить УО из ГИС при доступности helper, иначе вручную | Не показывать пустой реестр как сбой синхронизации |
| УО, нет домов | Загрузить дома выбранной УО | Поисковый фильтр не равен пустой базе |
| Нет выбранного дома/перечня | Явно предложить выбор | Нельзя подставлять другой перечень автоматически |
| Перечень без состава | Добавить работы актуального справочника УО | Не использовать универсальный вымышленный справочник |
| Есть состав без проверки | Проверить локальный состав | Проверка не должна автоматически размещать в ГИС |
| GIS IMPORT_SENT | Проверить готовность проекта | Не называть готовым до фактического GIS-status |
| GIS DRAFT и нет несохранённых изменений | Разместить после контроля | Размещение отдельно от сохранения проекта |
| GIS APPROVED перечень | Перейти к планированию | Изменение состава требует отдельного сценария отмены |
| GIS CANCELLED перечень | Редактировать/сохранить/разместить по подтверждённому сценарию | Предупредить про зависимые планы/факты/оценки |
| Исторический план с неизвестными современному перечню строками | Просмотр и объяснение ограничения | Опасную обратную запись не предлагать |
| Месяц без плана/факта | Предложить предшествующий шаг или ручное заполнение | Не объявлять данные готовыми |
| Факт локально заполнен/изменён | Проверить/разместить соответствующую область | Не скрывать, что массовая отправка затронет размещённые месяцы |
| Оценка локально сформирована | Сохранить проект, в том числе без актов | Отсутствие акта не ошибка сохранения |
| Оценка DRAFT с неполными актами | Подготовить/проверить акты | Для размещения проверять действующие ограничения |
| Оценка DRAFT с годными актами | Разместить допустимые месяцы | Оценки, уже размещённые, не должны блокировать остальные |
| Ошибка/очередь остановлена | Причина + продолжить с проблемного месяца | Успешные месяцы не отправлять повторно |
| GIS/helper отключён | Понятное объяснение сетевой блокировки | Локальные действия сохраняют доступность |
| Операция выполняется | Прогресс и область операции | Нельзя переключением контекста направить ответ другой сущности |

## Перечни — существующая развилка
`registry_workflow.refresh_work_lists` проверяет status и fingerprint текущего состава:
- APPROVED → просмотр и переход к плану.
- IMPORT_SENT → запрос статуса импорта.
- DRAFT без dirty → размещение.
- LOCAL/NOT_FOUND/CANCELLED/DRAFT при отсутствии строк → добавить работу; при отсутствии успешной проверки → проверить; иначе → сохранить/подготовить проект.
- Unknown/error → проверить фактическое состояние ГИС вместо догадки.
Это текущее поведение модели, а не гарантия, что каждый экран оптимален.

## Помесячное и периодное действие
- `view_month` обозначает **только открытую таблицу**; `action_scope` — месяц либо все доступные месяцы года/перечня.
- Период может быть частично заполнен, частично размещён и содержать ошибки: нельзя описывать одним флагом «готово» без разбивки.
- Рекомендация на уровне периода строится по `MonthState` и `quality_step` / `fixation_step`, а не только по открытому месяцу.
- При частичной готовности основной путь — открыть конкретный отсутствующий месяц; массовое перезаполнение требует отдельного явного намерения.
- Для качества проект можно сохранить без актов, а размещение требует валидировать только реально отправляемые допустимые месяцы.
- Месяцы вне периода перечня должны быть видимы как недоступные, а не выглядеть ошибочными.
- При изменении выбора во время фоновой операции удерживать контекст старого задания и корректно применить новый только после завершения.

## Последовательность обратной связи
**idle → waiting / confirmation → running (scope/progress) → success | error (причина, частичный результат, retry) → refreshed stable state.**
Различать ошибки сети, валидации, отсутствие идентификаторов, недоступную GIS-сессию и конфликт local/remote.

## Границы тестирования
- `tests/test_ui_workflow.py`: первичное действие, проект без актов, частичный период, контекст, busy, очередь.
- `tests/test_registry_ui.py`: выбор, локальная проверка, DRAFT/APPROVED, dirty fingerprint.
- `tests/test_ui_clarity.py`: видимые массовые команды, группировка локальных/GIS действий, подписи, масштаб.
- `tests/test_ui_scale.py`: 100/125/150% и 1366x768, 1600x900, 1920x1080 в обеих темах.
- `tests/test_quality_assessment.py`, `tests/test_gis_downstream_sync.py`: акты, удаление remote-связей, исторические строки.
Наличие теста ≠ подтверждение живым Windows/GIS прогоном; явно отмечай, что было проверено.
