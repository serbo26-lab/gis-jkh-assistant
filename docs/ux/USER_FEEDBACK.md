# Наблюдения пользователей и реальная обратная связь по UX

Этот файл — **реестр проверяемых свидетельств**, а не сбор персональных данных. Здесь нельзя записывать идентификаторы УО, реальные адреса/домовые GUID, имена/контакты сотрудников, cookies, авторизационные заголовки, необезличенные HAR, скриншоты с реквизитами и информацию, позволяющую узнать клиента.

## Типы свидетельств
- **Документированная обратная связь по версии:** проблемы с воспроизводимыми описаниями, включая известные замечания к dev55 в `docs/ux-dev56.md`. Это не то же самое, что новое наблюдаемое исследование.
- **Наблюдаемая UX-сессия:** сотруднику поставлена конкретная задача; записываются обезличенная роль, версия, шаги, задержки, ошибки, запросы помощи и исход.
- **Сообщение пользователя о проблеме:** слова пользователя в кратком пересказе, версия и воспроизведение. Не превращать одно свидетельство в статистику.
- **Экспертная гипотеза:** идея агента/разработчика, которую ещё предстоит проверить. Никогда не помечать как пользовательскую жалобу.

## Уже известная исходная обратная связь (не новые тесты)
По `docs/ux-dev56.md`: после проверки пользователем dev55 были отмечены скрытые массовые команды, смешение сетевых и ручных команд в одном списке, неочевидные элементы раскрытия, обрезание подписей и несовпадение системного заголовка Windows с темой. Это **исторические замечания к dev55**; их устранение в dev56 описано в документации, но степень удовлетворённости пользователя нынешней версией требует отдельного наблюдения.

## Проведение пользовательских сессий
1. Получить согласие на наблюдение и, отдельно, на запись экрана, если она вообще нужна.
2. Не объяснять заранее путь кнопок; дать нейтральное задание, например «Разместите факт за март без изменения февраля».
3. Попросить участника озвучивать ожидания, не подсказывать ответ; отмечать остановки, возвраты, неверные предположения.
4. Оценивать разные уровни опыта (новичок/опытный), типовые одиночные и массовые задачи, при необходимости разные размеры Windows.
5. Использовать фиктивные данные и тестовый gateway. Записывать только обезличенные результаты и явные измерения; при невозможности безопасно обезличить — не включать материал.
6. Повторить тот же сценарий после изменения UI. Не приписывать улучшение одному изменению без сопоставимых условий.

## Что запрещено утверждать
- «Пользователям неудобно» по одному мнению агента или отсутствию теста.
- «Ускорили работу на 40%» без измерений и описания выборки.
- «Соответствует всем 10 эвристикам» по статическому чтению Python.
- «Этим пользуется большинство УО» без данных.
