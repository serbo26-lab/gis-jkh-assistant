# Устройство проекта и разработка

## Рабочий процесс

В приложении семь разделов: «УО», «Дома», «Перечни работ и услуг», «Планирование», «Фиксация работ и услуг», «Оценка качества», «Настройки». В «УО» находятся выбор организации, её реквизиты и подписанты; в «Домах» — карточки домов и связанные импорты. Связи, форматы Excel и бизнес-правила при переносе не менялись.

Пользователь выбирает УО, дом и перечень, готовит план, вносит факт и формирует оценку с актами. Планирование и месячные операции требуют размещённого перечня. Проект оценки можно сохранить без актов; размещение проверяет документы для включённых работ.

## Код

| Область | Реализация |
| --- | --- |
| Запуск и интерфейс | `__main__.py`, страницы и общие виджеты в `app/`; PySide6, Qt Widgets, QSS |
| Хранение | `database/repository.py`, модели, `AtomicConnection`, хранилища актов и реквизитов |
| План и факт | `work_planning.py`, `work_fixation.py`, сопоставление и импорт в `work_lists/` |
| Оценка и PDF | `quality_assessment.py`, `quality_automation.py`, `acceptance_act_details.py`, генераторы PDF |
| Обмен с браузером | `gis_integration/local_gateway.py`, проверка организации в `organization_context.py`, `browser-extension/background.js` |
| Файлы Excel | `gis_files/`: импорт домов, справочников, расширенных сведений и экспорт перечня |
| Установка помощника | `browser/helper_installation.py`, навигация браузеров, мастер в `app/helper_setup_dialog.py` |

Расширение выполняет запросы в авторизованной вкладке ГИС. Настольная программа не принимает логин и пароль пользователя. Перед командой и запросами записи проверяется организация. Локальный gateway слушает только loopback; его состояние подключения не подтверждает успешное применение ответа.

Сведения УО содержат ОГРН, КПП и отдельные идентификаторы организации. В карточке дома различаются GUID объекта жилищного фонда, GUID ГИС, GUID ФИАС и уникальный номер ГИС. Их нельзя заменять друг другом без подтверждённого соответствия. При импорте УО название выбирается из сокращённого наименования, с полным в качестве резервного.

## Данные и инварианты

В Windows данные находятся в `%LOCALAPPDATA%\GIS JKH Assistant\`, на Linux используется `XDG_DATA_HOME` или `~/.local/share/`. База, настройки и локальные файлы хранятся отдельно от EXE. `database/paths.py` сохраняет перенос старого имени каталога.

- Автосохранение при ошибке оставляет ввод в редакторе. Переходы и закрытие не должны терять несохранённые значения.
- Импорт плана охватывает строки и метаданные одной транзакцией. Некорректный ответ не заменяет прежний план.
- Синхронизация сохраняет пользовательские акты, локальные файлы фотографий, связи, внеплановые и исторические строки. Отсутствие объекта в неполном ответе не подтверждает удаление.
- Импорт Excel сначала проверяет весь набор и показывает изменения. Пустые ячейки сохраняют прежние значения; явно введённый ноль остаётся значением. Сопоставление не зависит от порядка строк.
- Версии файлов ГИС служат диагностикой. Импорт проверяет структуру и нужные поля, а не отвергает неизвестный номер версии.
- Область месячной операции отделена от месяца просмотра. Массовая отправка ограничивается годом и периодом перечня; прежние записи за его пределами сохраняются.
- PDF создаётся до замены автоакта. Файл, связи и снимок реквизитов сохраняются вместе. Изменение карточек не переписывает существующие документы.
- Реквизиты выбираются по дате акта; неоднозначный выбор требует решения пользователя. Частичные сведения заказчика и печатные подстановки не подтверждают полномочия или подписание.
- При закрытии фоновые задачи и обработчики результатов завершаются до закрытия базы. Следующая операция очереди после запроса закрытия не запускается.

## Локальная работа

Разработка и Windows-сборка используют Python 3.12. Установка зависимостей:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Обычный запуск обращается к пользовательскому профилю. Для экспериментов создавайте отдельную `Repository` и подменяйте gateway, как в `tests/test_ui_workflow.py`. Для проверки EXE задавайте отдельный `LOCALAPPDATA` дочернего процесса. Рабочие базы, HAR с сессиями, выгрузки и персональные документы в Git не добавляются.

```powershell
.\.venv\Scripts\python.exe -m gis_jkh_assistant
```

Проверки:

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
node --test
.\.venv\Scripts\python.exe -B tools/package_browser_helper.py --check
```

Qt-тесты используют временные базы и имитации ответов. Они не доказывают работу авторизации или записывающих операций в реальной ГИС. История изменений и проверок выпусков хранится в CHANGELOG. Для исследования нативных падений сохранены workflow `diagnose-linux-qt.yml` и тестовый plugin `tools/qt_diagnostic_plugin.py`; приложение этот plugin не загружает.

Размер интерфейса в настройках зафиксирован на 100%. Нативный DPI обрабатывает Qt; существующие регрессии масштабирования не отключаются.

## Сборка Windows

Программа собирается в один EXE. Файлы помощника включены в ресурс `browser/assets/browser-helper.zip`; мастер также использует подготовленную папку рядом с EXE. После изменения расширения обновляйте ресурс:

```powershell
.\.venv\Scripts\python.exe -B tools/package_browser_helper.py
```

Команды сборки и упаковки из корня репозитория:

```powershell
$buildPython = (Resolve-Path ".\.venv\Scripts\python.exe").Path
$savedBuildPath = $env:PATH
try {
    $pythonDirectory = Split-Path -Parent $buildPython
    $env:PATH = "$pythonDirectory;$env:SystemRoot\System32;$env:SystemRoot;$env:SystemRoot\System32\Wbem"
    & $buildPython -m PyInstaller --clean --noconfirm --onefile --windowed --paths src --collect-data gis_jkh_assistant.browser --name "GIS JKH Assistant" src/gis_jkh_assistant/__main__.py
    if ($LASTEXITCODE -ne 0) { throw "Ошибка сборки EXE" }
} finally {
    $env:PATH = $savedBuildPath
}
& $buildPython -B tools/package_windows.py
```

Собирайте в отдельном Python-окружении. Каталоги сторонних инструментов в `PATH` могут подменить DLL при упаковке: при локальной проверке библиотека ICU из Poppler вызвала ошибку загрузки Qt. Для контрольной сборки использован `PATH` с каталогом виртуального окружения и системными каталогами Windows.

`tools/package_windows.py` формирует ZIP по явному списку: `GIS JKH Assistant.exe`, `browser-extension/manifest.json`, `browser-extension/background.js`, `README.md`. Флаг `--no-readme` исключает инструкцию; `--exe` и `--output` задают другие пути. Остатки прежней сборки и дополнительные файлы каталогов в архив не попадают. Папка помощника соответствует проверяемому встроенному ресурсу. Ошибка упаковки не заменяет предыдущий архив.

Версия приложения задана в `VERSION` и `__init__.py`; версия помощника находится в манифесте и встроенном ресурсе. Их согласованность проверяется тестами. Эти значения входят в EXE и помощник; отдельные VERSION.txt и BUILD_INFO.json для работы не нужны. Описание GitHub-релиза содержит только версии программы и помощника. Коммит и SHA256 EXE записываются в итог шага GitHub Actions.

Workflow `build-windows.yml` проверяет проект, собирает EXE и вызывает тот же упаковщик. При успешной сборке `main` обновляется существующий `dev-latest`; PR создаёт только проверочную сборку. Техническая история выпусков хранится в [CHANGELOG](../CHANGELOG.md).
