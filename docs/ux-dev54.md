## Принятая модель

**Контекст → текущий этап и одно рекомендуемое действие → синхронизация и
дополнительные команды → операция → данные.**

Контекст УО/дом/перечень/год компактен и одинаков по смыслу. Stepper отражает
реальные состояния, а область следующего шага объясняет блокировку. Локальные
команды живут у таблицы; сетевые — в области процесса; fallback — в меню
файлов; опасные — в отдельном меню с пояснением области воздействия.

Выбор месяца всегда задаёт **просмотр** таблицы. Scope определяет **область
действия**: один месяц либо доступные месяцы перечня в выбранном году. При
периоде подсказка явно говорит, что таблица показывает один месяц. Основное
действие определяется агрегатом месяцев, а не состоянием показанного месяца.
В оценке качества уже размещённые удалённые оценки пропускаются существующей
очередью и не блокируют размещение других месяцев проверкой своих актов.
В фиксации прежний сценарий обновляет все заполненные месяцы области, в том
числе размещённые; это явно указано в пояснении перед действием.
При смешанном периоде с пустыми месяцами рекомендуемое дозаполнение открывает
конкретный пустой месяц и месячный scope. Готовые данные других месяцев не
переформируются по основной кнопке. Массовое заполнение остаётся дополнительным
действием с предупреждением о замене данных всего периода.
Если в качестве нет ни оценки, ни факта, следующий шаг ведёт к фиксации.
В смешанном периоде месяцы без оценки и факта явно учитываются как не вошедшие
в отправку. UI не объявляет весь период завершённым по одному размещённому месяцу.

У качества ветка подготовки актов отображается отдельно: **проект можно
сохранить без актов**. Stepper не превращает акты в предварительное условие
сохранения. Для размещения используется существующая валидация каждой
включённой работы и акта нарушения качества.

Переход к следующему разделу переносит тот же контекст при включённом общем
выборе. Неразмещённый перечень сохраняется в общем контексте, но downstream
показывает причину недоступности вместо автоматической подмены другим.

## Проверка

Регрессии бизнес-сценариев проверяются существующим набором тестов. UI-тесты
используют временную SQLite и фиктивный gateway: выбор следующего действия,
проект без актов, размещение с актами, смешанный scope, общий контекст,
продолжение очереди, обе темы, реальные геометрии 1366×768 / 1600×900 /
1920×1080. Скриншоты строятся из настоящих Qt-виджетов, а не HTML-концепта.

Защита контекста действует и для программных обновлений: выполняющаяся операция
сохраняет свой объект при смене общего выбора в другом разделе. Переход кнопкой
workflow между фиксацией и оценкой переносит также месяц и scope, если объект
и год совпадают. Год создания нового перечня не меняет год текущего объекта.
