# Обновление программы перед стабильным релизом

Статус: требования для следующего этапа разработки. Сейчас программа обновляется вручную заменой файлов из архива; автоматической проверки выпусков и установки обновления нет.

## Что уже есть

Версия программы задаётся в `VERSION`, версия помощника — в `browser-extension/manifest.json`. В сборку входит архив помощника. Сборка Windows из `main` публикуется в предварительном выпуске `dev-latest`; отдельный порядок публикации стабильных версий ещё нужно подготовить.

## Ожидаемое поведение

1. При запуске программа проверяет наличие новой стабильной версии в фоне. Отказ сети не мешает работе и не влияет на статус связи с ГИС ЖКХ. Проверка выполняется с ограничением времени и без постоянных повторов.
2. Стабильная версия предлагает только более новые стабильные выпуски. Предварительные `dev`-сборки не подменяют стабильную версию. Номера сравниваются как версии, а не как строки.
3. В настройках доступны текущая версия, результат проверки и ручная команда проверки. При наличии обновления видны новая версия и ссылка на изменения.
4. Скачивание и установка начинаются после явного действия пользователя. Перед установкой завершаются текущие операции обмена, закрывается программа и создаётся резервная копия данных. Файлы профиля пользователя сохраняются.
5. Загруженный пакет проверяется на соответствие выбранному выпуску и целостность до запуска установки. Ошибка скачивания или замены файлов оставляет работающую прежнюю версию; повторный запуск ГИС-команд после обновления не выполняется.
6. Если новой программе нужен другой помощник, она показывает требуемую версию и предлагает существующий мастер настройки. Обновление EXE само по себе не считается обновлением расширения в браузере.

## Что решить и проверить до выпуска

- Подготовить публикацию неизменяемых стабильных выпусков с версиями пакетов, контрольными суммами и требованиями к помощнику. Сохранить отдельный выпуск для разработки.
- Выбрать способ установки для текущей поставки ZIP: отдельный процесс замены файлов после выхода программы либо установщик. До реализации автоматической установки оставить явный переход к скачиванию и ручной замене.
- Предусмотреть восстановление при сбое установки и миграции базы: прежний EXE может быть несовместим с новой схемой, поэтому одного отката файлов программы недостаточно.
- Проверить обновление с предыдущей стабильной версии, отсутствие новой версии, недоступную сеть, повреждённый пакет, занятые файлы и прерывание установки. После обновления проверить сохранность базы, шаблонов и вложений, а также сообщение о несовместимом помощнике.

Эти требования не меняют текущий порядок обновления и не включают автоматическую установку в текущий PR.
