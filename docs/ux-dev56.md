# dev56: понятные действия и доступный размер интерфейса

## Основание

Проверка пользователем dev55 показала конкретные проблемы: массовые команды скрывались в меню, ручные действия и обмен с ГИС попадали в один список, раскрывающиеся секции имели неясные обозначения, подписи кнопок обрезались, а системный заголовок Windows не следовал теме. В HAR страницы информации об организации найден штатный запрос получения реквизитов текущей УО.

## Модель действий

| Раздел | Контекст и рекомендуемый шаг | Видимые действия ГИС | Локальные действия и файлы |
| --- | --- | --- | --- |
| Дома | УО → реестр → выбранный дом → перечни | Добавить текущую УО из кабинета; загрузить дома, управление и перечни всей УО | Добавить/изменить УО вручную; добавить дом; импортировать/экспортировать файлы |
| Перечни | Выбранный дом и период → состав → проверка → проект → размещение | Получить перечни дома; синхронизировать текущий проект; отдельный резервный обмен XLSX | Работы, суммы, шаблоны состава и локальные XLSX-файлы рядом с данными |
| Планирование | Размещённый перечень → план → ГИС | Загрузить существующий план; разместить/обновить | Заполнить и распределить план; отдельная очистка |
| Фиксация | Перечень, год и область месяца/периода → факт → размещение | Загрузить и разместить выбранную область | Заполнить по плану; очистить; работа с фото и внеплановыми строками |
| Качество | Факт → оценка → акты → проект → размещение | Загрузить оценку; сохранить проект; разместить | Формирование оценки и актов; проверка; отдельные опасные действия |
| Настройки | Общий выбор, тема и масштаб | Состояние существующего помощника | Масштаб 100/125/150%; светлая/тёмная тема |

Основной следующий шаг остаётся один. Дополнительные команды обозначаются назначением и областью: «для всей УО», «для выбранного дома» или выбранной областью месяца/периода. Скрытие второстепенных файловых команд допустимо; основные массовые сценарии доступны прямо на странице.

## Получение УО

Браузерный помощник выполняет GET `/ppa/api/rest/services/ppa/organizations/details` с контекстом `/organization/information` через уже авторизованную страницу. Используются название, ОГРН, КПП и существующие поля идентификаторов организации. Перед локальным сохранением показывается проверка реквизитов. Совпадение ОГРН означает существующую УО, а не создание второй копии. Ручной комментарий и ранее введённые значения сохраняются.

HAR служит локальным источником структуры запроса/ответа. Сам файл, заголовки авторизации, cookies и сведения конкретной организации не включаются в репозиторий. Тестовые данные вымышлены. Запрос сохранения сведений организации в ГИС не выполняется; модели и миграции не меняются.

## Доступность и оформление

- Меню имеют одну стандартную стрелку, без дублирования текстового значка и стрелки Qt.
- Команды раскрытия называют секцию и действие: «Показать»/«Скрыть». Иконки выполняются SVG, а не шрифтовыми символами.
- Подписи действий участвуют в расчёте минимальных размеров; области действий перестраиваются при изменении ширины.
- Масштаб сохраняется как настройка интерфейса и не изменяет рабочий контекст, таблицы или данные.
- Windows использует системный заголовок, кнопки сворачивания/разворачивания/закрытия и обычные границы изменения размера. DWM переключает светлый/тёмный режим Windows 10; точные цвета заголовка и текста из tokens доступны в Windows 11. Неподдерживаемые атрибуты безопасно игнорируются.
- Проверка выполняется в обеих темах на 1366×768, 1600×900 и 1920×1080. Вертикальная прокрутка рабочего содержимого допустима; горизонтальная прокрутка остаётся внутри широких таблиц.

## Границы проверки

Автоматические тесты используют отдельные временные SQLite и подмену ответов ГИС, не действующую рабочую базу пользователя. Геометрия и изображения проверяются на настоящих Qt-виджетах. Нативные атрибуты Windows проверяются отдельно с безопасным отказом на неподдерживаемой платформе. Проверка по HAR подтверждает структуру команды; она не заменяет живой прогон всех операций ГИС.
