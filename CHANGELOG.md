# Changelog

## 0.1.0.dev25 — 2026-10-01

### Планирование работ и услуг
- вместо заглушки добавлен рабочий раздел «Планирование»;
- план доступен только для перечней, уже размещенных в ГИС ЖКХ и имеющих сохраненный GUID;
- локальный план хранится отдельно для каждого размещенного перечня и календарного года;
- состав работ при первом создании плана сохраняется как снимок размещенного перечня;
- для каждой работы доступны помесячные количества с января по декабрь;
- «Количество в плане» автоматически считается как сумма месячных значений;
- месяцы вне периода размещенного перечня блокируются;
- конкретные даты необязательны: количество можно вводить без календаря;
- двойной щелчок по месячной ячейке открывает календарь для добавления нескольких конкретных дат;
- добавлено автоматическое равномерное распределение количества из перечня по полному периоду;
- переходящие и многолетние периоды распределяются по всему периоду корректно, без повторного начисления полного количества в каждом году;
- автоматическое распределение очищает старые конкретные даты, чтобы они не конфликтовали с новым количеством;
- подготовлены поля для будущего хранения GUID плана и состояния обмена с ГИС ЖКХ.

## 0.1.0.dev24 — 2026-10-01

### Широкий формат импорта тарифов
- лист «Тарифы» теперь поддерживает удобную структуру «один дом = одна строка»;
- история тарифа заполняется вправо любым количеством повторяющихся пар «Действует с» / «Тариф, руб./м² в месяц»;
- пустые пары между заполненными допускаются и пропускаются;
- старый вертикальный формат dev23 остается совместимым;
- сформированный приложением XLSX теперь сразу создается в широком формате с запасом колонок для истории тарифа;
- настоящие Excel-даты с отображением ММ.ГГГГ распознаются как месячные даты, а ДД.ММ.ГГГГ — как точные даты;
- повторные точки с тем же значением тарифа не мешают автоматическому подбору тарифа для периода перечня: реальным изменением считается изменение суммы.

## 0.1.0.dev23 — 2026-10-01

### Массовый импорт площадей и тарифов
- на вкладке «Дома» добавлено формирование собственного XLSX-шаблона по домам выбранной УО;
- шаблон содержит отдельные листы «Площади», «Тарифы» и «Инструкция»;
- адреса и скрытые идентификаторы домов заполняются автоматически, поэтому пользователю остается перенести площади и историю тарифов;
- импорт показывает предварительное количество обновляемых площадей, новых тарифных точек и замен существующих значений;
- существующие тарифы не удаляются молча, если строка была убрана из XLSX: импорт только добавляет или обновляет явно указанные значения;
- числа принимаются с запятой, точкой и пробелами-разделителями.

### Даты тарифов
- дата начала тарифа теперь поддерживает оба формата: ММ.ГГГГ и ДД.ММ.ГГГГ;
- ММ.ГГГГ сохраняется как первый день месяца с признаком месячной точности;
- точная дата ДД.ММ.ГГГГ сохраняется без округления;
- окончание предыдущего тарифа рассчитывается как календарный день перед следующим изменением;
- старые тарифы автоматически мигрируют как месячные даты без потери существующей логики перечней;
- расчет тарифа для перечня по-прежнему требует, чтобы один тариф покрывал весь месячный период без изменения внутри него.

## 0.1.0.dev21 — 2026-10-01

### Повторное использование процентов распределения
- в окне «Распределение планируемой суммы» добавлены действия «Сохранить % для шаблона» и «Загрузить % для шаблона»;
- проценты сохраняются у выбранного пользовательского шаблона и доступны в перечнях других домов, созданных из того же шаблона;

- загрузка процентов не меняет тариф, площадь и итоговую планируемую сумму: эти значения по-прежнему берутся из текущего перечня и карточки дома;
- сохраненные проценты загружаются только если состав текущего перечня совпадает с составом шаблона, чтобы не распределить значения по неправильным строкам;
- если для шаблона уже есть сохраненное распределение, приложение запрашивает подтверждение перед заменой.

## 0.1.0.dev20 — 2026-09-30

### Тарифы как история изменений
- тариф больше не требует ручного указания даты окончания;
- пользователь задает только сумму и месяц/год, с которого начинает действовать новое значение;
- тариф действует до следующего явно указанного изменения;
- если новых записей нет, последний известный тариф автоматически продолжает действовать в следующих месяцах и годах;
- пример: 08.2020 = 22,00; 08.2021 = 23,00; следующее изменение только 08.2025 = 24,00 — значит 23,00 действует с 08.2021 по 07.2025;
- предыдущие и последующие границы действия пересчитываются автоматически при добавлении, изменении и удалении записи;
- нельзя создать две разные записи изменения тарифа с одной и той же датой начала;
- при добавлении следующей записи по умолчанию предлагается тот же месяц и следующий год, но дату можно изменить вручную.

### Совместимость
- тарифы, созданные в dev19 с явными периодами, при открытии базы преобразуются в последовательность изменений по датам начала;
- последний тариф становится открытым и действует до следующего изменения.

### Расчет перечня
- при поиске тарифа для планируемой суммы теперь учитывается перенос последнего известного значения на последующие годы;
- если внутри периода перечня есть следующее изменение тарифа, один тариф не выбирается произвольно — такой период должен рассчитываться по тарифным отрезкам.

## 0.1.0.dev19 — 2026-09-30

### Карточка дома
- добавлено поле «Площадь к начислению, м²»;
- площадь сохраняется отдельно для каждого дома и редактируется с тем же автосохранением, что остальные поля карточки;
- добавлен блок «Тарифы по периодам»;
- для одного дома можно хранить любое количество тарифов;
- у каждого тарифа задаются значение, месяц/год начала и месяц/год окончания;
- тарифы можно добавлять, изменять и удалять независимо друг от друга;
- при удалении дома его тарифы удаляются вместе с карточкой.

### Связь с расчетом перечня
- форма «Распределение планируемой суммы» теперь предзаполняет площадь из карточки дома, если у перечня еще нет собственной сохраненной площади;
- тариф автоматически подставляется только если один тариф дома полностью покрывает период выбранного перечня;
- если период перечня пересекает несколько разных тарифов и нет одного тарифа на весь период, автоматическая подстановка тарифа не выполняется;
- сохраненные непосредственно в перечне тариф и площадь имеют приоритет над справочными значениями дома.

### Архитектура на будущее
- тарифы хранятся как самостоятельные записи с периодом действия, чтобы позже использовать их в разделах публикации сведений о тарифах ГИС ЖКХ;
- текущая версия использует их только как источник предзаполнения для планируемой суммы.

## 0.1.0.dev16 — 2026-09-30

### Размещение перечня
- исправлена ошибка размещения `Unrecognized field "houseTypeCode"`;
- причина: поиск перечней возвращает расширенный объект WorkList, а endpoint размещения принимает сокращенную модель WorkListAlter;
- перед размещением помощник теперь формирует объект ровно в том составе, который отправляет веб-интерфейс ГИС ЖКХ;
- из корня исключены служебные поля поиска: `houseTypeCode`, `summary`, `status`, `organizationName`, `agreement` и другие;
- элементы работ также очищаются до полей, принимаемых endpoint размещения;
- справочные объекты `work`, `workType` и `okei` передаются только как `code + guid`;
- поле `unit` при размещении формируется так же, как в штатном запросе веб-интерфейса.

### Браузерный помощник
- версия расширения повышена до 0.1.2;
- idle long-poll теперь возвращает явный JSON-ответ 200 вместо 204;
- это убирает ложные `net::ERR_ABORTED`/красные записи для нормального ожидания команды в DevTools;
- помощник игнорирует idle-ответ и продолжает ожидание без выполнения команды.

## 0.1.0.dev14 — 2026-09-30

### Обмен с ГИС ЖКХ
- добавлен первый рабочий контур автоматической загрузки перечня в уже открытый личный кабинет ГИС ЖКХ;
- Windows-сборка теперь содержит папку `browser-extension` с помощником для Chrome/Edge;
- помощник выполняет команды непосредственно в открытой авторизованной вкладке ГИС ЖКХ и не сохраняет логин/пароль в приложении;
- добавлена кнопка «Загрузить в ГИС ЖКХ»;
- программа автоматически формирует XLSX из выбранного локального перечня, передает его в браузер, загружает в файловое хранилище ГИС ЖКХ и запускает импорт;
- после импорта программа пытается найти проект по GUID дома и точному периоду перечня;
- добавлена кнопка «Проверить статус в ГИС»;
- добавлена отдельная кнопка «Разместить информацию» с подтверждением;
- размещение и загрузка оставлены разными действиями.

### Статусы
- у локального перечня сохраняются GUID проекта ГИС, GUID загруженного файла и GUID задания импорта;
- сохраняются последний известный статус ГИС, время проверки и последняя ошибка;
- локальный статус меняется на «Проект в ГИС ЖКХ» при DRAFT и «Размещен в ГИС ЖКХ» при APPROVED;
- в карточке перечня отображается отдельная строка состояния ГИС ЖКХ.

### Интеграция с браузером
- приложение запускает локальный шлюз только на 127.0.0.1;
- расширение получает команды только от локального приложения;
- запросы к ГИС выполняются внутри уже открытой вкладки личного кабинета через штатный AngularJS-контекст страницы;
- пользовательские cookies и данные авторизации не сохраняются в локальной БД приложения.

### Сборка
- ZIP актуального GitHub Release теперь содержит:
  - `GIS-JKH-Assistant.exe`;
  - `browser-extension/`;
  - `VERSION.txt`.

## 0.1.0.dev12 — 2026-09-30

### Заполнение от планируемой суммы
- добавлен второй способ заполнения выбранного перечня: «Распределить от итоговой суммы»;
- расчет работает с любым количеством позиций выбранного пользовательского шаблона;
- пользователь вводит одну итоговую планируемую сумму и процент распределения для каждой позиции;
- форма показывает рассчитанную сумму по каждой строке до применения;
- расчет можно применить только когда сумма процентов составляет ровно 100%;
- позиции с 0% остаются пустыми;
- после применения используются допустимые для ГИС ЖКХ поля «Количество + Стоимость»;
- «Цена» и «Объем» очищаются автоматически;
- количество устанавливается по числу месяцев периода перечня: полный год = 12, 05–12 = 8, переходящий 06–05 = 12;
- итоговая сумма и проценты распределения сохраняются в локальной БД;
- при создании перечня на основе выбранного сохраненная плановая сумма и проценты копируются вместе с остальными данными;
- расчет выполняется одной транзакцией, без поочередного сохранения каждой ячейки.

### Расчет и округление
- суммы рассчитываются по формуле «итоговая сумма / 100 × процент»;
- денежные значения округляются до копеек;
- возможный остаток округления автоматически добавляется к позиции с наибольшим процентом, поэтому сумма строк всегда точно совпадает с итоговой;
- добавлены тесты на пример 100 000 руб. с распределением 10/6/13/10/9/12/18/22%.
