# Changelog

## 0.1.0.dev54 — 2026-10-07

### Рабочий процесс вместо панели команд
- проведён аудит пяти рабочих разделов и настроек; модель и ограничения описаны в `docs/ux-dev54.md`;
- введены переиспользуемые заголовок страницы, компактный контекст, карточки, lifecycle/stepper, область одного рекомендуемого действия, меню дополнительных команд и опасных действий;
- следующий шаг определяется сохранённым состоянием данных, выбранной областью и доступностью помощника; причины блокировки показаны прямо на экране;
- страницы используют общую логику «контекст → этап → действия → операция → данные», сохраняя различную компоновку там, где это нужно сценарию.

### Разделы
- **Дома**: master/detail, компактный реестр, карточка с секциями; действия УО и массовая синхронизация отделены от выбранного дома, удаление вынесено из основного потока;
- **Перечни**: существующий перечень выбирается отдельно от раскрываемого блока создания; период, состояние ГИС и историчность видны без чтения GUID; состав остаётся на всю ширину; локальные изменения, проверка, подготовка проекта и размещение имеют разные места и этапы;
- основной путь подготовки нового проекта автоматически получает техническую основу через существующий helper и использует прежний импорт; ручные XLSX-сценарии сохранены в меню файлов;
- **Планирование**: следующий шаг — заполнение, проверка/размещение или фиксация; статус показывает локальный, изменённый или размещённый план; сравнение содержимого после успешного обмена хранится как UI-настройка без изменения моделей и миграций;
- **Фиксация**: состояние каждого месяца, агрегированный следующий шаг для периода, единые действия scope вместо скрытых дублирующих year-кнопок; локальное заполнение и очистка находятся у таблицы;
- **Качество**: формирование → акты → проект → размещение; проект доступен без актов, требования актов объясняются при размещении; аннулирование появляется только для применимой оценки; статус периода определяется всеми выбранными месяцами;
- **Настройки**: общий/независимый контекст, сохранённый выбор темы, понятное объяснение подключения.

### Контекст и операции
- устранена подмена общего выбранного перечня при обновлении селекторов во время перехода; недоступный перечень/год остаётся в общем контексте с объяснением;
- год создаваемого перечня отделён от года текущего рабочего объекта;
- Qt workers используют единый OperationStatus: действие, месяц, счётчик, ошибка; очереди сохраняют прежнюю последовательность и продолжение с месяца ошибки;
- при обмене блокируются смена контекста и редактирование; ошибки видны в badge месяца даже при сохранённом удалённом статусе;
- локальное автоматическое сохранение и существующие подтверждения опасных операций сохранены.

### Темы и проверка
- одна система семантических light/dark tokens для фона, поверхностей, текста, границ, выделения и состояний;
- современная левая навигация с встроенными SVG-иконками; цвета таблиц и палитра диалогов обновляются вместе с темой;
- добавлены UI-регрессии на временной SQLite с fake gateway: primary/lifecycle, scope, общий выбор, блокировки, очереди, темы и ширина всех страниц при 1366×768, 1600×900, 1920×1080;
- Windows build проверяется также в PR; rolling `dev-latest` обновляет сборку и ссылку тега на актуальный main;
- Ubuntu CI устанавливает нативные библиотеки Qt и шрифты для выполнения настоящих UI-тестов offscreen; ошибка одной ОС не отменяет проверку другой;
- SQLite, миграции, модели, интеграционные команды и браузерный помощник не менялись.

## 0.1.0.dev49 — 2026-10-07

### Актуализация старых перечней
- для размещенного перечня добавлена кнопка **«Отменить перечень в ГИС ЖКХ»**;
- используется штатный запрос ГИС ЖКХ **cancel/worklist**, подтвержденный новым HAR;
- после успешной отмены перечень сохраняет свой GUID и состав, получает статус **«Отменён»** и становится доступен для редактирования;
- локальные планирование, фиксация и оценка качества этого перечня очищаются, поскольку ГИС ЖКХ удаляет их при отмене;
- у отмененного перечня и проекта теперь можно добавлять и удалять работы из актуального справочника;
- добавлена команда **«Очистить состав»** для полного удаления старых строк;
- добавлена команда **«Заменить по шаблону»**: выбранный пользовательский шаблон сопоставляется с актуальным справочником организации, устаревшие позиции пропускаются с предупреждением;
- добавлена кнопка **«Сохранить изменения в ГИС ЖКХ»** для отмененного перечня или проекта;
- сохранение выполняется напрямую штатным **save/worklist** с тем же GUID перечня; каждая локальная строка предварительно разрешается через актуальный справочник организации;
- после сохранения измененный перечень становится проектом и может быть снова размещен существующей кнопкой **«Разместить информацию»**;
- размещенный перечень теперь заблокирован от локального редактирования состава и периода до его отмены;
- проверка статуса существующего перечня выполняется по GUID, поэтому изменение периода проекта не теряет связь с ГИС ЖКХ.

### Что подтвердил HAR
- старые строки действительно могут возвращаться ГИС ЖКХ со статусом справочника **DELETED** и вызывают **WorkTypeIsNotActualException** при сохранении или размещении;
- после удаления устаревших строк и добавления работ из актуального справочника тот же отмененный GUID успешно сохраняется как **DRAFT**;
- операция **«Аннулировать информацию»** в этом HAR не выполнялась, поэтому в dev49 автоматизирована безопасно подтвержденная ветка **«Отменить перечень»**.

### Версии
- приложение: **0.1.0.dev49**;
- ГИС ЖКХ помощник: **0.1.26**.

## 0.1.0.dev48 — 2026-10-07

### Старые перечни и изменившийся справочник ГИС ЖКХ
- обратная синхронизация больше не требует полного совпадения состава локального перечня и данных планирования/фиксации/оценки;
- если старая работа присутствует в плане ГИС ЖКХ, но уже отсутствует в ответе самого перечня, она импортируется как историческая строка без принудительной привязки к текущему справочнику;
- планирование восстанавливает такие строки, их месячные количества и даты;
- фиксация умеет добавлять отсутствующие исторические плановые строки и загружать по ним фактические показатели;
- оценка качества также принимает исторические строки и их GUID/акты;
- исторический план можно просматривать, но его обратная перезапись в ГИС ЖКХ блокируется, если текущий состав перечня ГИС уже не содержит эти работы;
- в диалоге загрузки плана счётчик месячных значений теперь считает только реально заполненные месяцы, а не все 12 ячеек каждой работы.

### Общий выбор
- выбранный перечень на вкладке **«Перечни работ и услуг»** сохраняется при обновлении страницы, если дом не изменился;
- при переходе между вкладками с включённым **«Общим выбором»** общий контекст повторно применяется после обновления страницы;
- список **«Все перечни дома»** больше не должен самопроизвольно перескакивать на последний перечень при возврате на вкладку.

### Версии
- приложение: **0.1.0.dev48**;
- ГИС ЖКХ помощник: **0.1.25**.

## 0.1.0.dev46 — 2026-10-07

### Массовые действия по МКД
- блок на вкладке **«Дома»** переоформлен как **«Сведения о МКД (массовые действия)»**;
- над кнопками добавлена отдельная строка состояния операции;
- **«Импорт домов из XLSX…»** перенесён в строку локальных XLSX-инструментов рядом с шаблоном площадей и тарифов;
- массовые кнопки размещены отдельной сеткой, чтобы блок можно было расширять новыми массовыми операциями;
- во время массовой операции другие массовые действия и XLSX-импорт домов блокируются;
- на уровне локального шлюза команды ГИС ЖКХ теперь выполняются последовательно: новый запрос ожидает завершения предыдущего.

### Живой прогресс перечней
- во время получения массового реестра показывается **«Получено перечней: N»** без номера страницы;
- после получения отображается **«Сопоставление N/Всего»**;
- при записи новых перечней отображается **«Сохранение N/Всего»**;
- для обновления уже связанных перечней показывается отдельный счётчик статусов;
- прогресс передаётся из браузерного помощника в приложение отдельным каналом, не дожидаясь завершения всей команды.

### Автоматический шаблон перечня
- добавлена кнопка **«Получить / обновить шаблон из ГИС ЖКХ»**;
- приложение запускает штатный экспорт **EXPORT_WORK_LIST_V2**, отслеживает задание в реестре файлов и скачивает готовый XLSX через файловое хранилище ГИС ЖКХ;
- полученный официальный файл проверяется существующим парсером и сохраняется как техническая основа экспорта;
- ручная кнопка **«Выбрать XLSX вручную…»** сохранена как резервный способ;
- реализация основана на полном HAR-цикле: постановка экспорта → реестр статусов → готовый resultContentGuid → скачивание XLSX.

- новый акт добавляется в массив `qualityAct`, проходит `checkunique/quality-act` и загрузку в filestore;
- запрос изменения отправляется через тот же `POST /workplanning/api/rest/services/approve/estimation`, при этом текущая версия передаётся со статусом `DRAFT` и `dbStatus=APPROVED`;
- после изменения ГИС ЖКХ выдаёт новые GUID оценки и строк, поэтому приложение перечитывает remote state и обновляет локальные идентификаторы.

### Удаление акта
- подтверждено, что отдельного endpoint удаления акта не используется;
- для удаления акта он исключается из массива `qualityAct` при следующем `approve/estimation`;
- локально сохранённый акт теперь помечается на удаление до успешного размещения изменений;
- чужие/неизвестные приложению remote-акты сохраняются и не удаляются автоматически.

### Аннулирование оценки
- добавлена кнопка **«Аннулировать информацию»**;
- аннулирование выполняется подтверждённым запросом `PUT /workplanning/api/rest/services/cancel/estimation` с `workReportingPeriodGuid`;
- после аннулирования remote GUID оценки и строк очищаются, но локальные данные и файлы остаются для повторного формирования оценки;
- браузерный помощник повышен до **0.1.11**, версия приложения — **0.1.0.dev31**.

- выпадающие списки получили отдельную область стрелки, hover/pressed-состояния и оформление списка в стиле остальных элементов Windows 11;
- месяцы периода имеют минимальную ширину и больше не должны схлопываться рядом с годом.

### Формирование файла для ГИС ЖКХ
- добавлена кнопка «Сформировать XLSX» для выбранного перечня;
- при импорте пользовательского шаблона исходный XLSX сохраняется локально отдельно от базы;
- старые шаблоны, созданные до dev9, один раз запросят исходный официальный XLSX при первом формировании файла;
- сформированный файл создается на основе исходного шаблона ГИС ЖКХ, а не пересобирается с нуля;
- в копии шаблона заменяются houseGuid, период «с/по» и строки перечня;
- остальные части XLSX, включая служебные XML-части, справочники и настройки, переносятся без изменения;
- в файл попадают только фактически заполненные строки;
- перед выгрузкой проверяется один из допустимых режимов: «Цена + Объем + Кол-во» либо «Кол-во + Стоимость»;
- числа с запятой нормализуются для XLSX;
- работа сопоставляется со справочником исходного файла прежде всего по GUID.

### Данные
- в локальной БД добавлена ссылка на сохраненную копию исходного XLSX шаблона;
- добавлена автоматическая миграция существующей базы без удаления пользовательских данных.
